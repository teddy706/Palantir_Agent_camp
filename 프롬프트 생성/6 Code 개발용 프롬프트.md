나는 앞서 생성한 5개의 원천 데이터셋을 활용해 '네트워크 보안 이상 행위 및 계획 이탈'을 탐지하는 Python Transform 코드를 개발하려고 해. 아래 요구사항에 맞는 코드를 작성하여 `02.code` 폴더에 저장하고, 최종 가공 데이터셋을 생성해줘.

#### 1. 입력 데이터셋 (01.data 폴더 소스)
- 사용자 관리 데이터 (users)
- 네트워크 장비 접속 이력 데이터 (tacs_logs)
- 리눅스 서버 OS 로그 데이터 (os_logs)
- 장비유형별 명령어 위험도 기준 데이터 (cmd_master)
- 협력사 작업계획서 데이터 (work_plans)

#### 2. 데이터 가공 및 조인(Join) 로직
1. **[명령어 위험도 및 즉시경고 매핑]**
   - `tacs_logs` 데이터셋을 기준으로, 실행된 '실행 명령어'와 해당 장비의 '장비유형'을 매핑하여 `cmd_master` 데이터셋과 조인(Join)해줘.
   - 이를 통해 각 접속 이력에 맞는 `장비유형별 위험도 점수`와 안티포렌식 명령어 여부인 `즉시경고 여부(Y/N)` 컬럼을 결합해줘.

2. **[작업계획서 이탈 및 승인 여부 판별]**
   - 위 결과 테이블에 `work_plans` 데이터셋을 '작업 대상 장비명'과 '신청자 사번(이름)'을 기준으로 Left Join 해줘.
   - [계획 이탈 판단 규칙]: `tacs_logs`의 '명령어 발생 시간'이 `work_plans`의 '승인된 작업 시작일시'와 '종료일시' 사이에 존재하지 않거나, 매칭되는 작업계획서가 아예 없다면 `is_unauthorized_plan` 컬럼의 값을 'Y'로, 계획 내 정상 작업이면 'N'으로 입력해줘.

3. **[OS 레벨 행위 맥락 검증 결합]**
   - 위 결과 테이블에 `os_logs` 데이터셋을 '로그 발생 시간', '장비명', '실제 수행 사용자 사번'으로 조인하여, TACS 상의 명령어 실행 시점과 실제 서버 내부 OS 감사로그(/var/log/*)의 `통과/차단 여부` 및 `로그 메시지 본문`이 일치하는지 확인할 수 있도록 컬럼을 통합해줘.

#### 3. 최종 출력 데이터셋 및 제약 사항
- 최종 가공 출력 데이터셋의 이름은 `detected_nw_anomalies`로 지정하고, `01.data` 폴더에 저장해줘.
- 이 데이터셋의 Primary Key(PK)는 고유한 일련번호인 `ANOMALY_ID`로 자동 생성되도록 코드를 작성해줘.
- 코드가 완성되면 성공적으로 빌드(Build)를 수행하여 데이터가 정상 적재되는지 확인해줘.
