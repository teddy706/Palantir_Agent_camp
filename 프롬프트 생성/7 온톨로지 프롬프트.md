데이터셋 빌드가 성공적으로 완료되었으므로, 다음 단계인 온톨로지(Ontology) 구성을 진행해줘. 가공 데이터셋과 원천 데이터셋을 활용해 Object Type, Link Type, Action Type을 정의하고 `03.ontology` 폴더에 저장해줘.

#### 1. Object Type (오브젝트 타입) 생성 및 매핑
다음 3개의 데이터셋을 기반으로 각각의 오브젝트 타입을 생성해줘.
1. `users` 데이터셋 ➡️ **'사용자'** 오브젝트 타입 생성
   - Primary Key: 사용자 ID
   - 표시 이름(Title Property): 사용자명
2. `detected_nw_anomalies` 데이터셋 ➡️ **'이상탐지이력'** 오브젝트 타입 생성
   - Primary Key: ANOMALY_ID
   - 표시 이름(Title Property): 실행명령어
3. `work_plans` 데이터셋 ➡️ **'작업계획서'** 오브젝트 타입 생성
   - Primary Key: 작업계획서 ID
   - 표시 이름(Title Property): 작업계획서 ID

#### 2. Link Type (링크 타입) 및 관계 정의
오브젝트 간의 상호 유기적인 조회를 위해 아래와 같이 링크를 연결해줘.
1. **[사용자 ↔ 이상탐지이력] 링크**
   - 관계: '사용자' 1 : N '이상탐지이력' (한 사용자가 여러 이상 행위를 유발 가능)
   - 연결 키: `detected_nw_anomalies.사용자이름(사번)` ➡️ `users.사용자 ID` (사번 기준 매핑)
   - 사용자 측 링크 이름: "발생한 이상탐지 목록"
   - 이상탐지이력 측 링크 이름: "행위자 정보"

2. **[사용자 ↔ 작업계획서] 링크**
   - 관계: '사용자' 1 : N '작업계획서' (한 사용자가 여러 작업 계획을 신청 가능)
   - 연결 키: `work_plans.신청자 사번(이름)` ➡️ `users.사용자 ID` (사번 기준 매핑)

#### 3. Action Type (액션 타입) 정의
NW보안팀이 모니터링 중 앱(Workshop)에서 즉시 보안 조치를 취할 수 있도록 2가지 액션을 만들어줘.
1. **액션 1: [이상행위 소명 요청]**
   - 대상: '이상탐지이력' 오브젝트
   - 파라미터: 소명요청 사유 (문자열, 필수 입력)
   - 규칙: 선택한 '이상탐지이력' 오브젝트의 특정 속성(예: 소명상태)을 '소명 대기'로 변경하고, 소명요청 사유를 해당 오브젝트에 기록하는 규칙 정의.
2. **액션 2: [보안 조치 및 계정 차단]**
   - 대상: '사용자' 오브젝트
   - 파라미터: 차단 사유 (문자열, 필수 입력)
   - 규칙: 선택한 '사용자' 오브젝트의 '상태' 속성을 "정상"에서 "보안 차단 잠금"으로 변경하고, '재직' 속성을 "보안 격리"로 즉시 변경하는 규칙 정의.

모든 구조를 정의한 뒤 온톨로지 게시(Save/Publish)까지 완료해줘.
