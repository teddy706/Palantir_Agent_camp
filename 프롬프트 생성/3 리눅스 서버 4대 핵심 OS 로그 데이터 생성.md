### [수정본 3 : 리눅스 서버 핵심 OS 로그 데이터 생성 프롬프트]

KT 네트워크 서버(Linux 환경) 내부에서 생성되는 시스템 로그 샘플 데이터를 50건 생성해줘. 이 데이터는 앞서 정의한 `사용자 관리 데이터` 및 `TACS 접속 이력 데이터`와 유기적으로 결합하여, 실제 OS 레벨에서 일어난 행위의 맥락을 검증하기 위한 원천 데이터야.

#### 1. 열 구성 및 데이터 형식 (A~G)

- **로그 발생 시간 (A):** `2026.06.19 HH:MM:SS` 형식, 실시간 유입을 모사하기 위해 시간순 정렬 (TACS 로그 시간과 초 단위로 동기화되어야 함).
    
- **장비명 (B):** 영문+숫자 조합. `TACS 이력 데이터`에 등장한 장비명(`USM_MCMA_VIP`, `DJ-HeMS105`, `AMF_GWANGJU_01`)과 정확히 일치해야 함.
    
- **로그 소스 파일 (C):** 다음 4가지 정의된 로그 중 하나를 지정
    
    1. `/var/log/secure` (보안로그: 사용자 인증, su 권한 전환, SSH 접속 관련)
        
    2. `/var/log/messages` (일반로그: 시스템 전반 운영 및 커널/데몬 이벤트)
        
    3. `/var/log/audit/audit.log` (감사로그: 시스템 호출, 중요 파일 변경 감사)
        
    4. `/var/log/bash_his.log` (계정별 bash_history: 사용자가 쉘에서 실제 실행한 명령어 기록)
        
- **접속 계정 (D):** 장비 내 실제 OS 계정 (`vsm`, `hems`, `imadmin`, `root`).
    
- **실제 수행 사용자 사번 (E):** **[중요 - 온톨로지 조인 키]** TACS를 통해 들어온 실사용자 사번 (`91241746`, `91355412`, `10152948` 등).
    
- **로그 메시지 본문 (F):** 실제 리눅스 시스템 표준 포맷을 모사한 텍스트.
    
- **통과/차단 여부 (G):** "Success", "Failed", "Denied", "Info" 중 하나.
    

#### 2. 데이터 패턴 및 해킹 시나리오 생성 규칙 (★핵심)

앞서 TACS 이력에서 설정한 **'김외주(91241746) 계정 탈취 시나리오(새벽 02:15 경)'** 시점에 4가지 로그 파일이 유기적으로 연동하여 증거를 남기는 패턴을 생성해줘.

- **패턴 1 (정상 작업자 행위 - 40행):**
    
    - 주간 시간대, `이정직(10152948)` 혹은 `박협력(91355412)`이 작업을 수행할 때 생성되는 표준 로그.
        
    - `/var/log/secure` ➡️ `sshd[12345]: Accepted password for hems...`
        
    - `/var/log/bash_his.log` ➡️ `[hems] cd /app; ls -ltr; cat config.conf`
        
    - `/var/log/messages` ➡️ `systemd[1]: Started Session 123 of user hems.`
        
- **패턴 2 (계정 탈취자 위험 행위 감시 - 10행):**
    
    - **새벽 02:15:00 ~ 02:16:30** 사이에 `AMF_GWANGJU_01` 장비에서 발생한 긴박한 해킹 로그 시퀀스.
        
    - **su 권한 상승 (보안로그):** `/var/log/secure`에 `su: pam_unix(su-l:session): session opened for user root by vsm(uid=501)` 기록 (Success).
        
    - **실행 명령어 은폐 시도 및 실행 (Bash 히스토리):** `/var/log/bash_his.log`에 `[vsm->root] whoami`, `[vsm->root] setm -mode active`, `[vsm->root] creboot -force`가 기록됨.
        
    - **커널 시스템 감사 (감사로그):** 해커가 강제 재부팅을 실행하는 순간 `/var/log/audit/audit.log`에 `type=USER_CMD msg=audit(...): auid=91241746 uid=0 cmd="creboot -force"` 형태로 커널이 이벤트를 가로채 감사 로그를 남김.
        
    - **시스템 다운 예고 (일반로그):** `/var/log/messages`에 `shutdown[9876]: Shutting down system immediately via user request` 형태의 경고 메시지가 남음.
        

#### 3. 출력 형식 및 시스템 제약 사항

- **Primary Key(기본키):** 행 고유 식별을 위한 일련번호 컬럼인 `OS_LOG_ID`를 추가하여 기본키(PK)로 지정해줘.
    
- **참조 무결성:** 본 데이터셋의 '실제 수행 사용자 사번' 및 '장비명'은 앞선 파일들의 데이터 범위와 완벽히 정합성을 이뤄야 해.
    
- **저장 경로:** 최종 산출물은 반드시 `01.data` 폴더 안에 저장해줘.
    
- 엑셀에 바로 붙여넣을 수 있도록 **탭 구분 테이블(TSV) 형식**으로 출력해줘.
    
- 헤더 행을 포함하여 총 50건의 행을 생성해줘.
