## 1. 배경 및 문제 정의

개별 보안 솔루션 대시보드가 보여주는 '조치완료·백신설치완료 99%'라는 수치 뒤에는, 장비 노후화·EOS·미지원 OS 등으로 인해 예외처리된 **1%의 보안 사각지대**가 존재한다. 공격자는 이 1%를 노리며, 각 보안 시스템(TACS, 서버백신, SecureInsight 등)이 파편화되어 있어 담당자가 알람 간 인과관계와 맥락을 파악하지 못하는 것이 현재의 한계다.

본 프로젝트는 **TACS 명령어 이력을 중심 축**으로 인프라·보안 상태를 교차 대조하여 사각지대의 이상 징후를 탐지하고, 사람이 개입하는 2단계 판정 구조를 통해 오탐을 정제하며 스스로 진화하는 규칙 체계를 Foundry 상에 구축하는 것을 목표로 한다.

## 2. 목표 (Goals)

- 보안 작업도 일일작업검토 수준으로 리뷰하고 관리되어야한다.
- 파편화된 보안 데이터(TACS·서버백신·SecureInsight·ITAM·NMS)를 Foundry 상에서 통합하여 단일 시계열 관점에서 조회 가능하게 한다.
- TACS 명령어 실행을 축으로 인프라/보안 상태 변화를 자동으로 교차 대조하여 이상 징후를 탐지한다.
- 장비 운영자(1차) → NW보안팀 담당자(2차)로 이어지는 판정 워크플로우를 통해 오탐을 걸러내고, 판정 이력을 데이터로 축적한다.
- 반복되는 오탐을 화이트리스트로 자동 편입시키되, 조건 충족 시 재검토되도록 하여 룰이 안전하게 진화하도록 한다.
- 모든 판정 및 예외처리 사유를 데이터 계보로 남겨 감사 추적성을 확보한다.

## 3. 성공 지표 (Success Metrics) — 초안, 확정 필요

캠프 종료 시점 정량 목표는 아직 확정되지 않았다. 아래는 논의를 위한 초안이며, 실제 수치는 NW보안팀과 협의 후 확정한다.

|지표|초안 목표|비고|
|---|---|---|
|파일럿 데이터 통합 완료|부록 A 전 항목 Foundry 적재|캠프 내 필수|
|유령자산(Shadow IT) 식별|TACS와 ITAM(server),NMS(network) 비교로 최소 1건 이상 실증|NMS가 5G스위치로 한정되어 있어 범위 제약 있음|
|이상 탐지 → 2단계 판정 워크플로우|End-to-End 시나리오 1개 이상 실증|Workshop 상에서 1차/2차 판정 화면 동작 확인|
|반복 오탐 재검토 로직|트리거 조건 1개 이상(N회 반복) 동작 확인|정확한 N값은 오픈이슈 (8번 참조)|
|AIP 기반 외부 위협 문서 파싱|KISA/ATT&CK 문서 업로드 → 후보 룰 산출 End-to-End 1건 이상 실증|파일 업로드 기반, 실시간 피드 아님|
|감사 로그 계보|판정 이력 100% 데이터 계보 기록|Foundry Ontology 감사 기능 활용|

## 4. 범위 (Scope)

### 4.1 In-Scope (캠프 기간)

- 부록 A에 명시된 실제 데이터의 Foundry 배치 업로드 및 통합
- TACS 유·무선 명령어 이력 기반 교차 감시 엔진 (서버백신알람, SecureInsight, 서버보안설정 로그 대조)
- TACS와 ITAM(server), NMS(network) 비교를 통한 유령자산 식별 (단, NMS는 5G스위치 자산 한정)
- 기존 금지 명령어 블랙/화이트리스트, 이상유형 분류체계, 킬체인 기반 시나리오를 초기 룰 시드로 흡수
- 1차(장비 운영자)-2차(NW보안팀) 2단계 판정 워크플로우 (Workshop UI)
- 반복 오탐 재검토(Safety Valve) 로직
- 판정/예외처리 이력의 데이터 계보 기록
- **KISA 보안공지·MITRE ATT&CK 등 외부 위협 문서를 파일로 업로드하고, AIP를 통해 문서 원문에서 공격 명령어 패턴을 파싱하여 동적 룰 마스터에 반영** (실시간 자동 수집이 아닌 수동 업로드 기반)

### 4.2 캠프 기간 검토 (9번 향후 확장 참조)

- KISA/ATT&CK 등 외부 위협 인텔리전스의 **실시간 자동 피드 수집** (캠프 기간은 문서 파일 수동 업로드 + AIP 파싱까지만 다룸)
- 시스템 간 실시간 API 연동 (배치 업로드로 대체)
- 작업계획서 전산 연동 기반 자동 정상판단 (샘플 1건만 확보되어 아이디어 단계 유지)
- ITAM/NMS 전 자산 대상 확장 (5G스위치 외 네트워크 자산 전체)

## 5. 사용자 및 역할 (Personas)

|역할|설명|주요 니즈|
|---|---|---|
|장비 운영자|현장에서 장비에 직접 접속·작업하는 담당자|본인 작업에 대한 소명을 빠르고 간단하게 입력하고 싶음|
|NW보안팀 담당자|전체 이상 징후를 모니터링하고 최종 판정하는 보안 담당자|개별 사이트를 오가지 않고 한 곳에서 맥락 있는 정보를 보고 판단하고 싶음|

## 6. 유스케이스 (Use Cases)

**UC-1. 이상 명령어 탐지 및 자동 대조** TACS에서 금지 명령어(또는 블랙리스트 패턴)가 실행되면, 시스템은 동시간대 서버백신알람 발생 여부, SecureInsight 미조치 취약점 상태 변화, 서버보안설정 로그(secure_bkup 등)의 비정상 흔적을 자동으로 대조하여 이상 징후 여부를 판단한다.

**UC-2. 유령자산 식별** 서버 장비는 ITAM에, 네트워크 장비는 NMS에 각각 등록되므로, 이 둘을 합친 자산 목록을 TACS 장비 목록과 비교하여 TACS 상에는 존재하나 ITAM·NMS 어디에도 등록되어 있지 않은 자산을 식별하고 목록화한다.

**UC-3. 1차-2차 판정 워크플로우** 이상 징후가 탐지되면 장비 운영자에게 소명 요청이 전달되고, 운영자가 Workshop 상에서 사유를 입력하면 NW보안팀 담당자가 이를 검토하여 [정상/실제위협/예외] 중 하나로 최종 확정한다.

**UC-4. 외부 위협 문서 기반 룰 확장 (AIP)** KISA 보안공지, MITRE ATT&CK 문서를 파일(텍스트/PDF 등)로 업로드하면, AIP가 문서 원문에서 공격에 사용된 명령어 패턴을 파싱하여 후보 룰로 추출한다. 추출된 후보 룰은 NW보안팀 담당자의 검토를 거쳐 동적 룰 마스터(기존 블랙/화이트리스트, 이상유형 분류체계와 통합)에 반영된다.

**UC-5. 동적 화이트리스트 반영 및 재검토** 2차 판정이 "정상"으로 확정되면 해당 패턴이 동적 화이트리스트에 등록되어 이후 동일 패턴에 대한 알람이 억제된다. 단, 재검토 트리거 조건(반복 발생 N회, 작업계획서 만료, 자산/사용자 확산) 충족 시 자동으로 2차 판정 큐에 재진입한다.

## 7. 기능 요구사항 (Functional Requirements)

### 7.1 데이터 통합

- FR-1: 부록 A의 각 데이터 파일(TACS 유·무선, 서버백신알람, SecureInsight, ITAM, NMS, 서버보안설정 로그, 작업계획서, 가이드라인 문서)을 Foundry에 배치 업로드 가능해야 한다.
- FR-2: 업로드된 원본 데이터는 민감정보(계정명, IP 등) 마스킹 또는 접근권한 통제 하에 관리되어야 한다.

### 7.2 교차 감시 엔진

- FR-3: TACS 명령어 실행 시각을 기준으로 서버백신알람, SecureInsight 상태 변화, 서버보안설정 로그를 동일 타임라인 상에서 대조할 수 있어야 한다.
- FR-4: 기존에 정리된 금지 명령어 블랙/화이트리스트, 이상유형 분류체계, 킬체인 기반 시나리오 탐지 로직을 초기 룰 세트로 반영해야 한다.
- FR-5: 서버 자산(ITAM)과 네트워크 자산(NMS)을 합산한 자산 목록을 TACS 장비 목록과 비교하여 불일치(유령자산) 항목을 자동으로 산출해야 한다.

### 7.3 판정 워크플로우

- FR-6: 이상 징후 발생 시 장비 운영자에게 소명을 요청하는 화면(또는 알림)이 제공되어야 한다.
- FR-7: NW보안팀 담당자는 1차 소명 내용과 근거 데이터를 함께 조회하여 [정상/실제위협/예외] 중 하나로 최종 판정할 수 있어야 한다.
- FR-8: 화이트리스트 등록 권한은 2차 판정(NW보안팀)에만 부여되어야 하며, 1차 판정만으로는 화이트리스트에 반영되지 않아야 한다.

### 7.4 규칙 진화 및 재검토

- FR-9: 2차 판정 결과가 "정상"인 경우 해당 패턴을 동적 화이트리스트에 자동 등록해야 한다.
- FR-10: 화이트리스트 항목은 아래 조건 중 하나라도 충족 시 자동으로 재검토 큐에 재진입해야 한다.
    - 일정 기간 내 N회 이상 반복 발생 (N값은 오픈이슈, 8번 참조)
    - 근거 작업계획서의 유효기간 만료
    - 동일 패턴이 다른 자산/사용자로 확산
- FR-11: 재검토 큐에 재진입한 항목은 2차 판정(NW보안팀) 담당자에게 배정되어야 한다.

### 7.5 외부 위협 문서 기반 룰 확장 (AIP)

- FR-12: KISA 보안공지, MITRE ATT&CK 등 외부 위협 문서를 파일 형태로 업로드할 수 있어야 한다.
- FR-13: AIP는 업로드된 문서 원문에서 공격 명령어 패턴을 파싱하여 후보 룰(제안) 형태로 산출해야 한다.
- FR-14: AIP가 산출한 후보 룰은 자동으로 룰 마스터에 반영되지 않고, NW보안팀 담당자의 검토·승인을 거쳐야 반영되어야 한다 (7.3의 2차 판정 권한 원칙과 동일하게, 최종 승인은 항상 사람이 담당).
- FR-15: 문서 업로드부터 후보 룰 산출, 승인, 룰 마스터 반영까지의 이력이 데이터 계보로 기록되어야 한다.

### 7.6 감사 및 추적성

- FR-16: 모든 판정 이력(1차 소명, 2차 확정, 사유, 시각, 담당자)은 삭제·수정 불가능한 형태로 데이터 계보에 기록되어야 한다.
- FR-17: 특정 자산의 예외처리 이력과 사유를 시점별로 조회할 수 있어야 한다.

|구분|요구사항|
|---|---|
|보안|실제 운영 데이터를 다루므로 캠프 환경 내에서도 접근권한 통제 및 민감정보 비식별처리 적용|
|데이터 처리 방식|실시간 API 연동이 아닌 정기 배치 업로드 방식 (캠프 기간 한정)|
|감사 추적성|판정 이력 및 화이트리스트 변경 이력은 영구 보관, 수정 불가|
|확장성|Phase 2 확장(외부 위협 인텔리전스, 실시간 연동, 자산 범위 확대) 시 재설계 최소화되는 구조로 설계|

## 9. Foundry 활용 (모듈 개요)

캠프 기간 동안 아래 Foundry 모듈을 활용하는 것을 전제로 하며, 세부 구현 방식은 FDE 조언을 받는다.

- **데이터 통합/파이프라인:** 부록 A 데이터의 배치 적재 및 변환
- **온톨로지:** 자산, TACS 세션/명령어, 알람, 판정 이력, 화이트리스트 룰 등 핵심 개체 모델링
- **Workshop:** 1차/2차 판정 UI 및 이상 징후 대시보드
- **Automate:** 재검토 트리거 등 조건 기반 자동화 로직
- **AIP:** KISA/ATT&CK 등 업로드된 외부 위협 문서에서 공격 명령어 패턴을 파싱하여 후보 룰을 산출 (캠프 기간 내 범위 포함, 단 실시간 자동 수집이 아닌 파일 업로드 기반)

## 9.1 향후 확장 계획 (캠프 기간 검토 상세)

- **외부 진화 루프의 완전 자동화:** 캠프 기간에는 KISA/ATT&CK 문서를 수동으로 업로드하여 AIP가 파싱하는 방식으로 진행하되, 향후에는 외부 피드를 실시간으로 자동 수집·주입하도록 고도화
- **실시간 연동 전환:** TACS, ITAM, NMS, SecureInsight 등과의 배치 업로드 → API 실시간 연동 전환 (연동 방식은 부서간 협의 및 기술 검토 필요)
- **작업계획서 시스템 연동:** 현재 아이디어 단계인 작업계획서 기반 정상 작업 자동 판단을 실제 데이터 연동으로 고도화
- **자산 범위 확대:** NMS 5G스위치 한정에서 전체 네트워크 자산으로 확대
